# مفتاح التوقيع — النسخ الاحتياطي والاستعادة

<div dir="rtl">

> **الملف الوحيد في هذا المشروع الذي لا يمكن إعادة بنائه.**
>
> كل شيء آخر — الكود، الأصول، الإصدارات، الاختبارات — يُستعاد من المستودع. مفتاح التوقيع لا.
> إن ضاع، انتهت قدرتك على تحديث التطبيق إلى الأبد.

## ١. لماذا يهم هذا المفتاح

Android يربط التطبيق **بمفتاحه لا باسمه**. النظام يرفض تثبيت أي تحديث فوق تطبيق مُثبَّت ما لم
يكن موقَّعًا بالمفتاح نفسه.

هذا يعني أمرين:

**حماية.** من ينسخ التطبيق ويعيد بناءه لا يستطيع دفعه إلى مستخدميك كتحديث. سيبقى تطبيقًا منفصلًا
يبدأ من الصفر.

**مسؤولية.** إن ضاع المفتاح:

- لا تستطيع نشر تحديث واحد بعده، للأبد
- كل مستخدم عليه **حذف التطبيق وفقد بياناته** ثم تثبيت نسخة بمفتاح جديد
- على Play، يبقى اسم الحزمة `com.athkar.app` محجوزًا لك وعاجزًا عن التحديث

## ٢. أين المفتاح

```
~/.athkar-signing/
├── athkar-release.jks        المفتاح نفسه (RSA 4096)
└── keystore.properties       المسار وكلمة المرور والاسم المستعار
```

صلاحيات `700` على المجلد و`600` على الملفين.

**الملفان لازمان معًا.** مفتاح بلا كلمة مروره عديم الفائدة تمامًا.

المجلد **خارج المستودع عمدًا**، و`.gitignore` يستبعد `*.jks` و`keystore.properties` حتى لا
يدخلا بالخطأ.

مفتاحك فعلًا. كل APK نُشر يحملها.

## ٤. النسخ الاحتياطي

### الخطوة ١ — اجمع الملفين في أرشيف

```bash
cd ~
tar czf athkar-signing-backup.tar.gz .athkar-signing/
```

### الخطوة ٢ — شفّره

الأرشيف الآن **غير مشفّر وكلمة مرور المفتاح بداخله نصًّا صريحًا**. لا تنقله قبل تشفيره.

```bash
gpg -c athkar-signing-backup.tar.gz
```

يسألك كلمة مرور تختارها أنت. تُنتج `athkar-signing-backup.tar.gz.gpg`.

```bash
rm athkar-signing-backup.tar.gz     # احتفظ بالمشفّر فقط
```

### الخطوة ٣ — سجّل بصمة الملف

```bash
sha256sum athkar-signing-backup.tar.gz.gpg
```

احفظ الناتج. يثبت لاحقًا أن النسخة لم تتلف أثناء النقل أو التخزين.

### الخطوة ٤ — انقله من جهازك أنت

```bash
scp <المستخدم>@<الخادم>:~/athkar-signing-backup.tar.gz.gpg .
```

### الخطوة ٥ — خزّنه في مكانين على الأقل

**مكان واحد ليس نسخة احتياطية.** أمثلة على أزواج جيدة:

- قرص خارجي + تخزين سحابي شخصي
- مدير كلمات مرور يقبل المرفقات + قرص خارجي

**واحفظ كلمة مرور الـ gpg في مكان مستقل عن الملف.** ملف مشفّر بكلمة مرور ضائعة = ملف ضائع.

### الخطوة ٦ — نظّف الخادم

```bash
rm ~/athkar-signing-backup.tar.gz*
```

الأصل يبقى في `~/.athkar-signing/` ليواصل البناء المحلي عمله. الأرشيف كان للنقل فقط.

## ٥. الاستعادة

### الخطوة ١ — فُكّ التشفير

```bash
gpg -o athkar-signing-backup.tar.gz -d athkar-signing-backup.tar.gz.gpg
```

يسألك كلمة المرور التي اخترتها عند التشفير.

بديل أقصر — يستنتج الاسم بحذف `.gpg`:

```bash
gpg -d athkar-signing-backup.tar.gz.gpg > athkar-signing-backup.tar.gz
```

### الخطوة ٢ — استخرج

```bash
tar xzf athkar-signing-backup.tar.gz
```

يُنشئ `.athkar-signing/` بالملفين وبصلاحياتهما الأصلية.

### الخطوة ٣ — تحقّق أنه المفتاح الصحيح

**لا تثق بالملف قبل هذا الفحص.**

```bash
keytool -list -v -keystore .athkar-signing/athkar-release.jks \
  -storepass "$(grep '^storePassword=' .athkar-signing/keystore.properties | cut -d= -f2-)" \
  | grep SHA256
```

يجب أن تطابق البصمة في القسم ٣ حرفًا بحرف. **ملف يُفكّ ويُستخرج لكن بصمته مختلفة ليس مفتاحك.**

### الخطوة ٤ — أعده إلى مكانه

```bash
tar xzf athkar-signing-backup.tar.gz -C ~
chmod 700 ~/.athkar-signing && chmod 600 ~/.athkar-signing/*
```

### الخطوة ٥ — احذف الأرشيف غير المشفّر

```bash
rm athkar-signing-backup.tar.gz
```

## ٦. على ويندوز و macOS

`gpg` و `tar` و `keytool` متوفرة على macOS ولينكس مباشرة.

على ويندوز: ثبّت [Gpg4win](https://gpg4win.org/)، ثم استعمل الأوامر نفسها في PowerShell.
`tar` و `keytool` متوفران أيضًا (الأول مع ويندوز 10+، والثاني مع أي JDK).

## ٧. أخطاء شائعة

| الخطأ | لماذا هو خطأ |
|---|---|
| نسخ `athkar-release.jks` وحده | بلا `keystore.properties` لا تُعرف كلمة مروره، والمفتاح عديم الفائدة |
| الاعتماد على أسرار GitHub كنسخة احتياطية | أسرار GitHub **لا تُقرأ بعد كتابتها**. لا يمكن استرجاع المفتاح منها أبدًا |
| نقل الأرشيف بلا تشفير | كلمة مرور المفتاح بداخله نصًّا صريحًا |
| حفظ كلمة مرور الـ gpg بجوار الملف | تشفير بلا فائدة |
| نسخة واحدة فقط | قرص واحد يعطب. حساب واحد يُغلق |
| رفع المفتاح إلى المستودع | حتى لو كان خاصًا: من يصل إلى المستودع يصل إلى تطبيقك |

## ٨. المفتاح في CI

توجد نسخة من المفتاح في أسرار مستودع `athkar-mobile`:

```
ATHKAR_KEYSTORE_BASE64
ATHKAR_KEYSTORE_PASSWORD
ATHKAR_KEY_ALIAS
ATHKAR_KEY_PASSWORD
```

يستعملها [`release.yml`](../../.github/workflows/release.yml) لبناء نسخ موقّعة.

> **ليست نسخة احتياطية.** أسرار GitHub تُكتب ولا تُقرأ — لا واجهة ولا أمر يسترجع قيمتها. إن ضاع
> الأصل فما في CI ضائع معه.

## ٩. Play App Signing

عند النشر على Google Play، تحتفظ Google بمفتاح التوقيع وتحتفظ أنت بـ **مفتاح رفع** فقط.

الفرق جوهري: **مفتاح الرفع قابل للتدوير إن تسرّب.** المفتاح الحالي ليس كذلك — تسريبه أو ضياعه
نهائي.

هذا وحده سبب كافٍ للنشر عبر Play بدل التوزيع المباشر حين يجدّ الأمر.
